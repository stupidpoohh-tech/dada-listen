이관을 시작하기 전에 확정한 사항들. 새로운 결정은 아래에 append 한다.
바뀐 결정은 지우지 말고 "변경됨" 표시와 함께 이유를 남긴다.

## D-001. 서비스 정의: 교실/학원 운영 도구

**결정.** 이 앱은 *개인용 갭필 생성기*가 아니라 **강사가 반 단위로 듣기 과제를 내고
누가 했는지 확인하는 도구**다.

**단계:**
- **지금 (②-a)** — 강사 1명(레포 소유자). 반은 여러 개. 라이브러리는 하나.
- **다음 (②-c)** — 학원 동료 강사가 합류. 라이브러리 공용, 반·과제는 강사별.
- **궁극 (④)** — 모르는 외부 강사도 가입해서 각자 공간을 갖는 SaaS.

**중요.** ④가 궁극 목표이므로 **스키마와 RLS는 처음부터 멀티테넌트로 짠다.**
강사 초대·가입·요금제 UI는 만들지 않는다. 하지만 모든 콘텐츠 행은 `owner_id`를
갖고, RLS는 테넌트 기준으로 쓴다. 테넌트가 지금 하나뿐일 뿐이다.

**이유.** 소유자 개념을 나중에 넣으려면 데이터 재이관이 필요하다. 지금 넣으면
컬럼 하나 값이다. 기존 앱은 `app/state` 문서 하나에 전부 들어 있어 소유자 개념이
아예 없다 — 이것이 이관에서 반드시 끊어야 할 구조다.

**검토했으나 채택하지 않음:**
- *개인 강사 도구(①)* — 숙제 체크가 원리적으로 불가능. 요구사항에 못 미친다.
- *학생 자습 도구(③)* — 학생이 자기 음원을 올리는 B2C. ASR 비용이 사용자 수에
  비례해 무료로 열면 적자이고, 저작권 리스크가 사용자 업로드로 넘어온다.
  다른 제품이므로 목표에서 제외.

## D-002. ASR로 업로드와 갭필을 직결한다

> **후속.** 제공자는 Deepgram 으로 확정 — D-013 참조.

**결정.** 업로드 즉시 서버에서 전사한다. **단어 단위 타임스탬프까지 받는다.**
Edge Function에서 Whisper 계열 API를 호출하고, API 키는 서버에만 둔다.

**이유.** 기존 앱에서 `generateGaps(passage)`는 오디오를 전혀 보지 않는다. 즉
"음성을 올리면 갭필이 생성된다"는 목적이 실제로는 성립하지 않고, 사람이 스크립트를
통째로 타이핑해서 잇고 있었다. ASR이 그 간극을 메우는 유일한 조각이다.

**타임스탬프가 진짜 이유다.** 전사문만으로는 기존 대비 "타이핑을 덜 한다"가 전부지만,
시간 정보가 붙으면 아래가 전부 열린다:
- 문장 클릭 → 그 문장만 반복 (기존의 손으로 맞추는 A/B 구간반복을 대체)
- 재생 중 현재 문장 자동 하이라이트
- **틀린 빈칸의 그 구간만 다시 듣기** ← 이 앱의 차별점
- 빈칸 참조가 안정적이 됨 (D-004 참조)

**비용.** 분당 약 $0.006. 강사만 업로드하므로 사용량이 예측 가능하다.
나중의 요금제를 위해 `asr_usage`에 강사별로 집계해 둔다.

**부수 효과.** 어차피 서버가 파일을 여므로 같은 자리에서 오디오만 뽑아 저장한다.
100MB mp4가 5MB 내외가 되고, 기존의 iOS Safari `captureStream()` 폴백이 통째로
불필요해진다.

## D-003. 데이터 모델: `passage: string` → `segments[]`

**결정.** 지문을 통짜 문자열로 두지 않는다. 문장(세그먼트) 단위로 쪼개고
각 세그먼트가 `start/end`와 단어별 타임스탬프를 갖는다.

**이유.** 기존 모델에는 시간 정보가 0이다. D-002가 주는 모든 이점이 이 모델을
전제로 한다. 핸드오프 README의 초안 스키마에도 `script jsonb -- 줄 단위
[{t, text, note}]`라고 적혀 있어, 원 작성자도 같은 방향을 감지했던 것으로 보인다.

---

## D-004. 빈칸은 토큰 인덱스로 저장하지 않는다

**결정.** 빈칸 위치를 저장할 때 **원본 단어 문자열을 함께** 저장한다.

**이유 — 이건 개선이 아니라 현존하는 버그다.** 기존 앱은 `gapIndices`를
`tokenize(passage)`의 배열 인덱스로 저장한다. 지문을 한 글자만 고쳐도 모든 인덱스가
밀려서 **빈칸이 조용히 엉뚱한 단어에 붙는다.** 경고도 없다.
단어를 함께 저장하면 최소한 드리프트를 감지해 경고할 수 있다.

## D-005. 학생 식별: 반 코드 링크 + 이름 탭

**결정.** 학생은 가입하지 않는다. 강사가 반 명단을 등록하고, 학생은 반 링크
(`/c/<code>`)를 열어 명단에서 자기 이름을 한 번 탭한다. 선택은 브라우저에 기억된다.

**이유.** 숙제 체크에는 학생 식별이 필수지만, 정식 계정은 중·고생 대상에서
가입 단계 이탈을 크게 만든다. 반 코드 방식은 마찰이 현재의 무로그인과 거의 같으면서
식별은 완전히 된다.

**한계 (수용함).** 기기를 바꾸면 이름을 다시 골라야 한다. 본인 확인이 약해서
친구 이름을 고를 수 있다 — 교실 맥락에서는 수용 가능한 수준으로 본다.
나중에 정식 계정으로 승급하는 길은 열어 둔다.

**반 코드는 전역 유일해야 한다** (④에서 다른 강사의 반과 충돌하면 안 됨).

## D-006. 채점은 하되, 타이핑으로 받지 않는다

**결정.** 갭필 답안은 **객관식/단어 은행 탭**으로 받는다. 타이핑 입력은 넣지 않는다.

**이유.** 숙제 확인에는 채점이 필요하지만, 모바일 타이핑은 학생 이탈을 만든다.
오답 보기는 **같은 지문 안의 다른 단어**에서 뽑으므로 추가 API 비용이 0이고,
기존 갭필이 결정론적이라 보기 생성도 결정론적으로 붙는다.

**함께 기록할 것.** 정답률뿐 아니라 실제 재생 구간도 집계한다. 학생이 아무것도
하지 않아도 "얼마나 들었는지"가 남는다.

**강사에게 보여줄 것.** 개별 점수보다 **"우리 반이 공통으로 틀린 빈칸"**이
수업 준비에 훨씬 유용하다. 대시보드의 1순위는 이것.

## D-007. 난이도는 저장하지 않고 생성한다

**결정.** 쉬움 10% / 보통 18% / 어려움 30%. 갭필 알고리즘이 결정론적이므로
**뷰에서 생성**한다. 강사가 손으로 켜고 끈 것만 override로 저장한다.

**이유.** 업로드 한 번으로 세 단계가 나오고 스키마가 늘지 않는다.
기존 앱은 `autoGap`이 `0.18`을 하드코딩하고 결과를 아이템에 굳혀서 한 단계뿐이었다.

## D-008. 갭필 선정 알고리즘 개선 (결정론은 유지)

**결정.** 아래를 개선하되 **같은 입력 → 같은 출력**은 절대 유지하고, 회귀 테스트를
함께 쓴다.

기존 `scoreWord`는 점수가 사실상 `글자 수 + 접미사 보너스`뿐이라:
- 빈도 데이터가 없어 흔한 긴 단어(`government`)와 어려운 단어를 구분 못 한다
- 점수순 탐욕 선택이라 **긴 단어가 몰린 문단에 빈칸이 쏠린다**
- 문장 중간의 고유명사를 거르지 않는다

개선: 소형 빈도 리스트 내장 · 세그먼트별 균등 분배 · 고유명사 제외 ·
같은 어간 중복 방지 · 객관식 보기 생성.

## D-009. 스토어 경계는 유지하되 `LDB` 시그니처는 버린다

**결정.** 영속화는 단일 모듈(`src/lib/store.ts`) 뒤에 가둔다는 원칙은 지킨다.
그러나 기존 `window.LDB`의 **함수 시그니처를 축자적으로 보존하지 않는다.**

**이유.** 핸드오프 CLAUDE.md는 시그니처 보존을 요구하는데, 이는 같은 문서가 몇 줄
아래에서 금지하는 동작과 충돌한다. `getBlobURL(path) → blob URL`이라는 시그니처
자체가 "전체를 받아서 Blob을 만든다"는 잘못된 동작을 API에 박아둔 것이다.
스트리밍으로 가면 이 함수는 존재할 이유가 없다.

## D-010. 미디어는 Storage + Range 스트리밍

> **변경됨.** Supabase Storage → Cloudflare R2. 판단의 근거(전체 다운로드를
> 버리고 Range 스트리밍 + 서명 URL)는 그대로이고 저장소만 옮겼다 — D-012 참조.

**결정.** 핸드오프 README의 판단을 그대로 따른다. Firestore base64 청크를 버리고
Supabase Storage로 옮긴다.

**추가로 정한 것 (README에 없음):**
- **버킷을 public으로 두지 않는다.** 유효기간 있는 **서명 URL**을 쓴다.
  자료가 시판 교재 음원일 수 있어(기존 앱 플레이스홀더가 "수능특강") URL만 알면
  누구나 받는 상태는 피한다. 서명 URL은 Range 요청과 문제없이 동작한다.
- Storage 경로를 `{owner_id}/...`로 나눈다 (④ 대비).

**함께 사라지는 기존 버그:** `ItemCard`가 `createObjectURL`로 만든 URL을 한 번도
revoke 하지 않아 카드를 열 때마다 파일 전체가 메모리에 쌓이던 누수.
그리고 카드를 열 때마다 전 파일을 재다운로드하던 문제.

## D-011. 백엔드를 Supabase에서 Neon으로 옮긴다

**결정.** DB·인증은 **Neon** (Postgres + Data API + Managed Better Auth).

**이유.** Supabase 무료 플랜은 **계정 전체에 걸쳐 활성 프로젝트 2개**가 한도이고,
조직을 새로 만들어도 합산된다. 두 슬롯이 이미 차 있어 이 프로젝트가 들어갈 자리가
없었다. 무료 범위 안에서 갈 수 있는 곳을 찾은 결과가 Neon이다 — 무료 플랜에
프로젝트 **100개**, Postgres RLS 완전 지원, 인증 내장.

**Supabase 무료 플랜은 어차피 이 앱에 맞지 않았다.** 프로젝트 개수보다 이쪽이
크다: 파일 저장 1GB, 대역폭 월 5GB. 10분짜리 mp3가 약 10MB이므로 음원 100개면
저장 한도가 끝나고, 학생 30명이 한 파일을 열 번씩 들으면 3GB다. 그리고 한도를
넘기면 **모든 서비스가 402를 반환한다** — 미디어만이 아니라 DB·인증·API가 함께
멈춘다. 학기 중에 앱 전체가 내려갈 수 있는 구조였다. 미디어를 R2로 분리한 이유가
여기 있다 (D-012).

**정지 동작도 다르다.** Supabase 무료는 7일 미사용 시 정지되고 대시보드에서 손으로
깨워야 한다 — 방학 중 학생 링크가 죽는다. Neon은 5분 뒤 scale-to-zero 하지만
요청이 오면 자동으로 깨어난다(콜드스타트 1초 미만).

**신원이 바뀐 지점.**
- `auth.uid()` (uuid) → **`auth.user_id()` (text)**. `pg_session_jwt` 확장이 JWT의
  `sub` 클레임을 돌려준다. Better Auth의 사용자 id가 uuid가 아니라 text다.
- 그래서 모든 `owner_id`가 `uuid` → `text`.
- `owner_id`에 **`default auth.user_id()`**를 걸었다. 클라이언트가 소유자를 실어
  보낼 필요가 없고, 남의 id를 실어 보내도 `WITH CHECK`이 막는다.
- `auth.users` 외래키를 없앴다. Neon Auth는 사용자를 `neon_auth` 스키마에 두는데
  그건 관리형이라 내부 구조가 바뀌면 마이그레이션이 깨진다. JWT의 `sub`를 그대로
  식별자로 쓰고 표시용 이름만 `teachers`에 둔다.
- 학생(anonymous) 차단 방식이 더 강해졌다. Supabase에서는 정책을 안 주는 방식이었는데,
  Neon에서는 **테이블 권한 자체를 주지 않는다** — 접근하면 정책 판정 전에 거부된다.

**정책의 모양은 하나도 바뀌지 않았다.** `owner_id = <현재 사용자>`, 자식은 부모를
통해 확인. 테이블·인덱스·제약도 그대로다. 함수 이름과 id 타입만 갈렸다.

**클라이언트.** `@neondatabase/neon-js` + `SupabaseAuthAdapter`. Data API가
PostgREST 호환이라 쿼리 표면(`.from().select().eq()`)이 동일하고, 어댑터가
`signInWithPassword`·`getSession`·`onAuthStateChange`·`resetPasswordForEmail`을
같은 이름으로 제공해서 `store.ts`의 인증부를 거의 그대로 뒀다.

**감수하는 것.**
- `@neondatabase/neon-js`가 **0.7.0-beta**다. 정식 전에 API가 바뀔 수 있어
  `db.ts` 한 파일에 가둬 뒀다.
- 번들이 커졌다(gzip 104KB → 143KB). 나중에 인증 경로를 코드 분할하면 준다.

**검토했으나 채택하지 않음:**
- *Supabase Pro ($25/월)* — 지금 규모에 과하다.
- *Supabase 셀프호스팅* — 코드는 한 줄도 안 바뀌지만 Docker 6개 서비스와 백업을
  직접 떠안는다. 강사 1명짜리 앱에 맞지 않는다.
- *PocketBase* — 운영은 제일 쉽지만 SQLite라 Postgres RLS를 통째로 버리고
  권한 로직을 앱 코드로 다시 짜야 한다.
- *Firebase* — 이미 계정이 있지만 이관에서 벗어나려던 대상이고, 반·과제·제출처럼
  관계가 많은 모델에 Firestore 보안 규칙은 표현력이 부족하다.

## D-012. 미디어는 Cloudflare R2

**결정.** 오디오·영상은 **R2**에 둔다. DB에는 오브젝트 키만 저장한다.

**이유.** **egress가 무료 티어든 유료든 항상 0원**이다. 이 앱은 오디오 스트리밍
앱이라 대역폭이 지배적인 비용인데, 그 항목이 통째로 사라진다. 저장은 10GB까지
무료다. D-011에서 본 Supabase의 5GB 대역폭 한도(초과 시 전 서비스 402)와 대비된다.

**서명 URL은 그대로 간다.** 버킷을 공개하지 않는다 — 자료가 시판 교재 음원일 수
있다(원본 앱 플레이스홀더가 "수능특강"). 서명 URL은 Range 요청과 문제없이 동작하므로
`<audio src>`에 그대로 넣어 스트리밍한다. D-010의 판단은 유효하고 저장소만 바뀌었다.

**서버가 하나 필요해졌다.** Supabase Edge Functions가 하던 자리를 대체할 곳이
필요하고, R2 바인딩이 네이티브인 **Cloudflare Workers**가 자연스럽다. 같은 자리에서
Deepgram 작업도 처리한다. 클라이언트는 `mediaApi.ts`의 계약(`/media/upload-url`,
`/media/play-url`, `/media/delete`)만 알고 R2를 모른다.

**R2 자격증명은 쓰지 않는다 (확정).** Workers에 호스팅하므로 R2를 **바인딩**으로
붙인다 — `env.MEDIA.get(key)`. access key / secret key를 만들 필요도, 어딘가에
보관할 필요도 없다. 관리할 비밀이 하나 줄어드는 것 자체가 이득이다.

바인딩은 Range 요청을 지원한다 (`R2GetOptions.range` 에 Headers를 넘기고
`writeHttpMetadata` 로 응답 헤더를 채운다). 그래서 Worker가 206 Partial Content로
직접 스트리밍할 수 있고, D-010의 "전체를 받아 Blob을 만들지 않는다"가 그대로 지켜진다.

S3 서명 URL 대신 **Worker가 HMAC로 서명한 토큰**을 URL에 실어 검증한다.
Deepgram이 파일을 받아갈 때도 이 URL을 쓴다 — 버킷은 계속 비공개다.
필요한 비밀은 `MEDIA_TOKEN_SECRET` 하나뿐이다.

**남은 숙제.** 무료 10GB도 200MB짜리 mp4 50개면 끝난다. 오디오만 뽑아 저장하면
20분의 1이 되지만 ffmpeg를 돌릴 자리가 필요하다. 당장은 원본을 저장하고,
용량이 실제로 문제가 될 때 다시 본다.

## D-013. 전사는 Deepgram Nova-3

**결정.** ASR 제공자는 **Deepgram**. URL을 넘겨 전사한다.

**가격으로 고르지 않았다.** 강사 1명이 월 300분을 전사한다고 할 때 제공자별
월 청구액은 Groq $0.20 / Deepgram $1.29 / OpenAI $1.80 / AssemblyAI $1.83이다.
차이가 월 1~2달러라 의미가 없다. 게다가 Deepgram은 $200 크레딧을 주므로
그 사용량이면 크레딧만으로 10년이 넘는다.

**구조로 골랐다.** Groq과 OpenAI는 파일을 **업로드**해야 하고 한도가 25MB다.
강사가 올리는 건 200MB짜리 mp4일 수 있어서, 오디오를 먼저 뽑아 줄여야 하는데
그러려면 ffmpeg를 돌릴 서버가 하나 더 필요하다. Deepgram은 **서명 URL만 넘기면
그쪽이 받아가고 영상에서 오디오까지 알아서 처리한다.** 한도는 2GB다.
월 1달러로 서버 컴포넌트 하나를 없앨 수 있다.

**함정 하나를 피했다.** OpenAI를 쓴다면 반드시 구형 `whisper-1`이어야 한다.
`gpt-4o-transcribe` / `gpt-4o-mini-transcribe`는 `verbose_json`을 지원하지 않아
**단어 타임스탬프를 받을 수 없다.** 우리 설계의 핵심이 타임스탬프라 치명적이다.

**응답이 스키마에 그대로 맞는다.** `utterances=true`로 요청하면 발화 단위로
`{start, end, transcript, words[]}`가 오는데, 이게 `segments` 테이블의 한 행과
정확히 대응한다. `words[]`의 `{word, start, end, punctuated_word}`는
`words` jsonb의 `{w, s, e}`가 된다.

**제공자는 얇게 감싼다.** 전사 호출을 한 모듈에 가두고 세그먼트 배열로 정규화해서
돌려준다. 나중에 바꿀 때 그 파일만 고치면 되게.

## 미결 (다음에 정할 것)

- **호스팅**: R2 와 서명 URL·Deepgram 워커 때문에 **Cloudflare Pages + Workers**
  가 사실상 정해진 것에 가깝다. 확정만 남았다.
- **오디오 추출 자리**: 원본 영상을 그대로 둘지, ffmpeg 를 돌려 줄일지 (D-012 참조).
  용량이 실제로 문제가 될 때 판단한다.
- **기존 Firestore 데이터**: 이관 스크립트를 쓸지 재업로드할지. 재업로드하면
  전사가 돌아 타임스탬프가 생기지만, 이관하면 시간 정보 없는 반쪽 아이템이 남는다.
  자료 개수를 확인해야 정할 수 있다.
- **오래된 미사용 학생 행 정리 정책.**
